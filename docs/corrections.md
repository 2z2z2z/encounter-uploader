# Новый тип заливки - "Корректировка результатов"

После игры автор начисляет командам (в командных играх) или игрокам (в одиночных) бонусное или штрафное время. Форма EN позволяет отправить только одну корректировку за раз. Новый тип даёт заполнить таблицу корректировок и отправить их последовательно, с паузой между запросами, как при заливке бонусов.

Одна строка таблицы = одна корректировка: один участник, один уровень (или "все"), тип, время, комментарий.

## Контракт EN (проверено на tech.en.cx 25.09.2026)

Официального API нет, работаем с HTML-формой.

- Форма: `GET https://{domain}.en.cx/GameBonusPenaltyTime.aspx?gid={gameId}&action=add`
  - `select[name="ddlEditCorrectionPlayers"] option` - участники игры: `value` = id, текст = имя. В командной игре это команды, в одиночной - игроки.
  - `select[name="ddlEditCorrectionLevels"] option` - уровни: `0` = "все", остальные `value` = id уровня, текст = номер уровня.
  - Оба списка приходят одним запросом, `levelId` не нужен.
- Отправка: `POST https://{domain}.en.cx/GameBonusPenaltyTime.aspx?gid={gameId}&action=save`, `application/x-www-form-urlencoded`
  - `radioCorrectionType` - `1` бонус, `2` штраф
  - `ddlEditCorrectionPlayers` - id участника
  - `ddlEditCorrectionLevels` - id уровня или `0`
  - `DaysList`, `HoursList`, `MinutesList`, `SecondsList` - целые числа. EN сам нормализует переполнение (90 секунд = 1 мин 30 с), в форме дни 0-30
  - `txtEditCorrectionComment` - комментарий
  - Кнопка отправки и скрытые поля не нужны.
- Ответ на отправку:
  - успех - 302 на `GameBonusPenaltyTime.aspx?gid={gameId}`
  - сессия истекла - 302 на `Login.aspx?return=...`
  - нет прав на игру - 302 на корень сайта
  - ошибка валидации - 200 со страницей формы и текстом в `.error`: "Ошибка. Укажите бонусное/штрафное время." (нулевое время), "Ошибка. Укажите в комментарии причину выдачи бонуса или штрафа." (пустой комментарий)
  - комментарий длиннее 2000 символов - 200 со страницей "Ошибка в системе"
  - несуществующий участник - 200 с пустой страницей, ничего не сохраняется
  - Итог: успех только при 302 на страницу корректировок этой игры, всё остальное - ошибка.
- EN не проверяет, что уровень принадлежит игре (чужой id уровня сохраняется). Поэтому id уровней берём только из формы.
- Комментарий EN выводит как HTML без экранирования.
- Список внесённых: `GET https://{domain}.en.cx/GameBonusPenaltyTime.aspx?gid={gameId}&lang=ru`, строки `tr.toWinnerItem`:
  - td0 - дата/время
  - td1 - участник: команда в `a[id$="lnkTeamInfo"]`, игрок в `a[id$="lnkPlayerInfo"]`
  - td2 - номер уровня (пусто = все уровни)
  - td3 - причина ("добавлен администратором" = ручная корректировка; иначе автоматическая: таймаут, бонусное задание, штрафная подсказка)
  - td4 - время текстом ("бонус 1 день 2 часа 3 минуты 4 секунды"); `a[id$="lnkBonus"]` - бонус, `a[id$="lnkPenalty"]` (`class="error"`) - штраф; `href` содержит `correct={id}`
  - td5 - комментарий
- Сводка результатов с учётом корректировок: `https://{domain}.en.cx/Administration/GameCorrection.aspx?gid={gameId}`

## Настройки

id: corrections
name: Корректировка результатов
isMultiBlocks: false
manualCodeAddition: true (строки добавляются вручную, есть колонка удаления, "Очистить" удаляет строки)
isGameScope: true

- `isGameScope`: поле "ID уровня" на странице настроек скрыто и не проверяется; игра может отсутствовать в списке активных игр домена (завершённая игра).
- Таблица привязана к игре (`config.gameKey`). Если тип открыт для другой игры (домен + gameId), а в таблице есть строки - предложить очистить. При отказе участники, которых нет в текущей игре, помечаются как не найденные. Привязка сохраняется только после ответа.
- Импорт JSON не меняет игру из настроек; статусы строк из файла другой игры сбрасываются в "не отправлено".

## Поля

- `correctionType` - переключатель "Бонус / Штраф", по умолчанию "Бонус"
- `participant` - выбор из списка участников игры, с поиском; хранится id и имя
- `correctionLevel` - выбор из "все" и номеров уровней игры, по умолчанию "все"
- `correctionTime` - дни, часы, минуты, секунды, по умолчанию 0
- `comment` - комментарий, обязателен, до 2000 символов
- `status` - только чтение: "не отправлено" / "отправлено" / "ошибка" (с причиной от EN)

Списки участников и уровней загружаются одним запросом к форме EN при открытии типа, с кнопкой обновления.

## Контролы

- `correctionGame` - загрузка участников и уровней игры (с обновлением), проверка привязки таблицы к игре
- `correctionType` - тип для всех строк
- `correctionLevel` - уровень для всех строк
- `correctionTime` - время для всех строк
- `correctionComment` - комментарий для всех строк

Контролы не трогают отправленные строки.

## Правила поведения

- Отправленная строка блокируется для редактирования (удалить её из таблицы можно). Чтобы начислить ещё раз, добавляется новая строка.
- Одновременно может идти только одна отправка. Строка, удалённая из таблицы во время отправки, не отправляется.
- Повторный запуск заливки отправляет только строки со статусом "не отправлено" и "ошибка".
- Перед отправкой строки проверяются: выбран участник из текущей игры, время больше нуля, комментарий 1-2000 символов. Строки с ошибками подсвечиваются, заливка не стартует.
- Перед отправкой загружается список внесённых корректировок. Если есть совпадения (участник, уровень, тип, время, комментарий) - показать их и дать выбор: "Пропустить совпадения" или "Отправить всё".
- Ошибка отдельной строки не останавливает заливку: строка помечается ошибкой, остальные уходят. Если сессия истекла или нет доступа к игре - заливка останавливается сразу.
- Пауза между отправками - стандартная для проекта.
- Окно внесённых корректировок: все записи игры, переключатель "только добавленные вручную" включён по умолчанию, кнопка обновления, ссылка на сводку результатов на EN.
- CSV: колонки `number, correctionType, participant, correctionLevel, correctionTime, comment, status`. Участник по имени, уровень по номеру ("все" или пусто = все уровни), тип "бонус"/"штраф", время `Д:ЧЧ:ММ:СС` (недостающие части слева: `10:00` = 10 минут). Нераспознанные имена и номера уровней подсвечиваются.
